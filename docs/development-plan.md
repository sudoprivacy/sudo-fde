# FDE SaaS 总体开发方案

本方案依据 `requirements.md` 和 Sudo-FDE-Studio 当前工作区。目标是交付可部署、可测试的 SaaS 实现。真实 Router 账务合同由外部服务提供；本项目实现 `fde-router/1` 适配合同，开发模拟器不能作为生产账务验收。用户已确认“按版本化适配合同实现，稍后接真实 Router”。本次不发布外网、不迁移原试用数据、不改动 Router。

## 架构与部署单元

浏览器 → FastAPI BFF → 私网 Pattern Service → SudoRouter。独立 worker 从 PostgreSQL 持久化任务队列领取任务。原 Pattern Service 的追问、推荐、匹配、概要、报告、修订、细化和反馈流水线作为受控源码依赖复用，原有任意 Provider 调用器和静态服务凭证入口不对外发布。

公共 API/UI、worker、内部 Pattern Service 共用 PostgreSQL，但每个事务都设置可信的 Tenant/User 上下文；所有私有表 FORCE RLS，并使用不带 superuser/BYPASSRLS 的运行账号。SQLAlchemy 应用鉴权和复合租户外键提供第二层保护。迁移账号独立。会话与用户身份是平台级对象，成员关系绑定组织，避免将同一用户复制为多个租户身份。

对象存储：生产 S3 兼容私有桶与服务端加密，开发本地目录。浏览器始终通过授权下载代理读取，避免资料撤销后长期有效的公开链接。对象键以 tenant/workspace 或 tenant/knowledge 分区。上传由 ClamAV 检查，解析/切片/embedding 在 worker 完成。

检索：工作区授权资料优先，随后租户授权资料；每次检索及引用读取都重新检查成员、知识库授权、文档版本和撤销状态。384 维内部多语言 embedding 或 Router embedding；本地开发提供明确标记的确定性向量替身。词项匹配与向量余弦混合排序，最多返回六个片段。第一版使用 PostgreSQL 索引筛选授权集合后精确重排，每次最多 10,000 个有效片段，超过容量明确拒绝，避免静默遗漏。规模扩大时切换 pgvector/HNSW 并保留相同权限过滤，不把近似向量结果作为授权依据。

首期禁用在线数据库和 MCP 直连入口。客户内网使用已有 fde-scan 生成只含结构/统计的 catalog，或上传 DDL。业务细化依据授权目录验证字段、粒度和缺口；真实数据记录仍留在客户网络。原本机 sudograph 数据库不直接挂到公网服务。

## 数据与权限

Tenant 与组织一对一。成员角色为 owner/admin/fde_member/billing_viewer；工作区默认私有，显式共享 editor/viewer。停用成员后在每个 HTTP 请求、任务开始和模型调用前重检，撤销不依赖缓存到期。billing_viewer 可看账务投影，不读业务正文。

业务记录包括证据、目录、产物、裁决、修订、细化绑定与导出。人工裁决和审计只追加；业务产物通过版本控制修改。修订先预览再应用，检查旧版本，保留更正与撤销记录。资料版本、片段、向量、来源、页码、有效期及授权完整保留。

## Router 与任务可靠性

服务间 JWT 仅 60 秒有效，绑定 audience、租户、用户、任务及输入摘要。浏览器无内部服务密钥。

每个用户请求使用 call_id；每个模型子调用根据任务、阶段与输入摘要生成稳定 operation_id。Router 授权目录和余额检查之后预占，再执行并结算。预算上限、子调用数量、输出 token、上下文长度与租户并发均有限额。

FDE 保存 Router 原始回执和用量投影，不维护充值余额或自行计算扣费。超时后的未知执行状态保留原幂等键；已返回输出但结算失败时只重试结算。worker 重启通过持久化租约恢复；Pattern 使用数据库 advisory lock 避免并发执行同一业务工作区。定期对账仅比较权威 Router 回执，差异进入审计，不能在本地伪造退款或余额。

## 实施顺序

1. 基础工程、配置校验、依赖锁定、数据库模型、迁移与 RLS。
2. 注册登录、会话/CSRF、邀请/重置、组织切换、成员与工作区权限。
3. Router 合同、模拟器、幂等与补偿、私网 Pattern 适配和异步任务。
4. 知识库、文档版本、敏感检查、授权 RAG、来源回链。
5. 六步业务工作台、裁决、修订、细化、YAML/OWL/BPMN/R2RML 导出。
6. 租户运营与审计、容器部署、备份恢复、故障测试、浏览器验收。

## 测试与交付

验收矩阵对应 FR-1–FR-5 和需求第九章：跨租户随机/已知 ID 拒绝、用户角色与即时撤销、短期服务身份、防 CSRF、限流、数据库侧 RLS、租户复合外键、余额不足零执行、并发重放/重启零重复结算、结算故障恢复、RAG 授权与删除/版本生效、敏感文本零外送，以及完整业务流程与可解析导出。

SQLite 用于快速测试；PostgreSQL 使用真实运行角色验证 RLS，不以 superuser 测试结果替代隔离验收。浏览器验收登录、组织切换、工作区、知识库和结果展示。Router 真实合同另设 opt-in 验收；模拟器测试通过不表示真实 Router 已对接。

生产启用前需提供真实 Router 合同端点、私有对象桶、ClamAV、邮件、内部 embedding/TLS 与独立密钥，并完成真实模型质量评测、备份恢复演练与运维容量验收。代码会拒绝开发默认密钥、SQLite、模拟 Router 及开发 embedding 的生产配置。
